## 1. 제품 개요 및 목표

도메인 정의서에 정의된 대로, 본 제품은 개인 투자자가 (1) 공식 투자자성향(KYC), (2) 심리적 성향(IPIP 신경성), (3) 실제 보유 자산배분(스크린샷 기반) 세 가지를 한 번에 진단받고, 본인의 실제 투자가 성향·심리 대비 적절한지 스스로 확인할 수 있도록 돕는 웹 애플리케이션이다.

### 비즈니스 목표

- 20~50대 직장인 투자자를 대상으로, 자기보고식 설문만으로는 드러나지 않는 "실제 투자행동과 심리적 손실감내도 간의 괴리"를 진단해주는 가치를 제공한다.
- 서비스가 성장할 경우 **최대 1000명이 동시에 접속하여 사용할 수 있어야 한다**는 것을 목표 규모로 둔다. (단, 이 목표와 2일 MVP 개발 범위의 관계는 8절 "가정 및 리스크"에서 별도로 다룬다.)

---

## 2. 목표 사용자

- **주 대상**: 20대~50대 직장인 투자자
- 본 PRD에서는 세부 페르소나(연령별 투자 성향, 구체적 사용 시나리오 등)를 별도로 정의하지 않는다. 2일 MVP 범위에서 실익이 크지 않다고 판단하여 생략한다.

---

## 3. 범위 (2일 MVP 기준)

### In-Scope

- 회원가입 / 로그인 / 로그아웃 (최소 인증)
- 투자자성향(KYC) 설문 응시 및 등급 산출
- IPIP 신경성 검사 응시 및 심리민감도 등급 산출
- 증권 계좌 스크린샷 업로드 → 자산 인식 → 자산군 분류 → 사용자 보정
- 종합 진단 결과(정합성/괴리 판정, 피드백 메시지) 확인
- 반응형 웹 UI (데스크톱/모바일 브라우저 대응, 네이티브 앱 없음)

### Out-of-Scope

도메인 정의서 7절과 동일하게 아래 항목은 범위 밖이다.

- 증권사 API를 통한 실시간 계좌 연동
- 실제 매매(주문 체결) 기능
- 실시간 시세 조회/연동
- 신경성 외 다른 Big Five 성격 요인 측정
- IPIP 50문항 전체 시행

추가로, **2일 · 1인 개발이라는 일정/리소스 제약상** 아래 항목도 이번 MVP 범위에서 제외한다.

- 진단 이력 추이 조회(과거 결과 비교/그래프) — 최신 진단 결과만 제공
- 비밀번호 재설정, 이메일 인증, 소셜 로그인 등 인증 부가 기능
- 관리자(어드민) 페이지
- 다국어 지원
- 웹 접근성(a11y) 대응
- 알림/이메일 발송
- 결제/구독 기능
- 실제 1000명 동시접속에 대한 부하 테스트 및 인프라 튜닝 (8절 참조)

## 4. 핵심 기능 요구사항 (FR)

도메인 정의서 5절의 4단계 유스케이스를 기반으로 하며, 도메인 정의서에는 없는 회원 인증 요구사항(FR-0)을 PRD 레벨에서 추가한다.

> **FR-0 추가 사유**: 도메인 모델상 모든 진단 결과(KycProfileResult, NeuroticismTestResult, HoldingsSnapshot, RiskDiagnosisResult)는 "사용자 참조"를 전제로 설계되어 있고, 재응시·재업로드 이력의 소유권 구분이 필요하다. 그러나 도메인 정의서는 진단 도메인 자체에 집중되어 있어 인증에 대한 언급이 없으므로, 서비스가 동작하기 위한 최소 전제조건으로 PRD에서 정의한다.

### FR-0. 회원가입/로그인

- FR-0.1 사용자는 이메일과 비밀번호로 회원가입할 수 있다.
- FR-0.2 사용자는 이메일과 비밀번호로 로그인/로그아웃할 수 있다.
- FR-0.3 로그인하지 않은 사용자는 진단 관련 기능(FR-1~FR-4)에 접근할 수 없다.

### FR-1. 투자자성향(KYC) 설문 응시

- FR-1.1 사용자는 10개 문항(각 1~5점)에 응답할 수 있다.
- FR-1.2 응답 완료 시 총점을 100점 환산으로 계산하고, 도메인 정의서 6절의 구간 기준에 따라 5단계 등급(안정형/안정추구형/위험중립형/적극투자형/공격투자형)을 산출한다.
- FR-1.3 산출된 결과(문항별 응답, 총점, 등급, 응시 일시)를 저장한다.
- FR-1.4 사용자는 재응시할 수 있으며, 재응시 시 새로운 결과가 별도로 생성된다.

### FR-2. IPIP 신경성 검사 응시

- FR-2.1 사용자는 10개 문항(각 1~5점)에 응답할 수 있다.
- FR-2.2 역채점 문항은 `6 - 응답값`으로 반전 처리 후 합산한다.
- FR-2.3 신경성 총점을 기준값과 비교하여 심리민감도 등급(높음/보통)을 산출한다.
- FR-2.4 산출된 결과(문항별 응답, 총점, 등급, 응시 일시)를 저장한다.
- FR-2.5 사용자는 재응시할 수 있으며, 재응시 시 새로운 결과가 별도로 생성된다.

### FR-3. 잔고 스크린샷 업로드 및 보정

- FR-3.1 사용자는 증권 계좌 잔고 화면 스크린샷 이미지를 업로드할 수 있다.
- FR-3.2 업로드된 이미지에서 종목명·수량·평가금액을 인식(OCR/AI 비전)한다.
- FR-3.3 인식된 종목별로 자산군(주식/채권/펀드/현금성자산 등)을 자동 분류한다.
- FR-3.4 자동 분류가 애매한 항목은 사용자가 화면에서 직접 확인하고 자산군을 수정할 수 있다.
- FR-3.5 보정 완료 후 자산군별 비중을 확정하여 보유잔고 스냅샷으로 저장한다.
- FR-3.6 사용자는 재업로드할 수 있으며, 재업로드 시 새로운 스냅샷이 별도로 생성된다.

### FR-4. 종합 진단 결과 확인

- FR-4.1 사용자는 가장 최근의 투자자성향 진단결과, IPIP 신경성 검사결과, 보유잔고 스냅샷 각 1건을 조합하여 종합 진단을 요청할 수 있다.
- FR-4.2 투자자성향 등급의 성향기준 비중과 실보유 자산배분을 자산군별로 비교하여 정합/괴리를 판정한다.
- FR-4.3 심리민감도가 '높음'이고 동시에 괴리가 있는 경우, 심리적 부담 안내를 결과에 포함한다.
- FR-4.4 정합인 경우 긍정적 피드백을, 괴리인 경우 조정 방향 피드백 메시지를 생성한다.
- FR-4.5 위 결과를 리스크 진단 결과로 사용자에게 화면에 표시하고 저장한다.
- FR-4.6 세 가지 입력(KYC/IPIP/잔고) 중 하나라도 결과가 없는 경우, 종합 진단을 요청할 수 없고 어떤 항목이 부족한지 안내한다.

## 5. 비기능 요구사항

- **동시접속**: 최대 1000명 동시접속을 목표 규모로 두고, 이를 고려해 API 서버는 무상태(stateless)로 설계하고 DB는 커넥션 풀을 사용한다. 단, 실제 부하 테스트·튜닝은 2일 MVP 범위에서 수행하지 않는다 (8절 참조).
- **반응형 웹 UI**: 데스크톱과 모바일 브라우저 화면 크기에 대응하는 반응형 레이아웃을 필수로 적용한다. 네이티브 앱은 개발하지 않는다.
- **접근성(a11y)**: 이번 프로젝트 범위에서 고려하지 않는다.
- **성능**: 별도의 응답시간 목표 수치는 정의하지 않는다. 단, 일반적인 웹 서비스 수준의 체감 응답성(수 초 이내 페이지 전환)을 목표로 한다.
- **보안(최소 사항)**:
  - 비밀번호는 해시(예: bcrypt)로 저장한다.
  - 인증이 필요한 API는 로그인 사용자만 접근 가능하도록 검증한다.
  - 업로드된 계좌 스크린샷 등 민감정보의 구체적 보관/파기 정책은 도메인 정의서 8절의 확인 필요 항목으로, 본 PRD에서 별도로 확정하지 않는다.

## 7. 일정 및 범위 우선순위

전체 개발 기간: **2일**, 1인 개발.

| 구간 | 목표 | 검증 |
|---|---|---|
| Day1 오전 | 프로젝트 셋업(프론트/백엔드/DB), 기본 스키마, FR-0(회원가입/로그인) | 회원가입 후 로그인하여 인증 토큰/세션이 발급됨을 확인 |
| Day1 오후 | FR-1(투자자성향 설문), FR-2(IPIP 신경성 검사) | 두 설문을 응시하고 등급이 저장·조회됨을 확인 |
| Day2 오전 | FR-3(스크린샷 업로드·인식·보정) | 스크린샷 업로드 후 자산 항목이 인식되고, 보정 후 자산군별 비중이 확정됨을 확인 |
| Day2 오후 | FR-4(종합 진단 결과), 반응형 UI 마무리 | 3종 입력을 결합해 정합/괴리 판정과 피드백 메시지가 표시됨을 확인, 모바일 화면 폭에서 레이아웃 확인 |

우선순위 원칙: FR-1, FR-2(순수 설문 로직)는 구현 난이도가 낮고 도메인 규칙이 명확하므로 먼저 완료해 안정적인 기반을 확보한다. FR-3(OCR/AI 비전)은 정확도·처리 흐름이 가장 불확실한 항목이므로 Day2 초반에 집중 배치하고, 시간이 부족할 경우 수동 입력 보정 UI를 우선 동작시키는 방식으로 축소할 수 있다. FR-4는 FR-1~3의 산출물에 의존하므로 마지막에 배치한다.

## 8. 가정 및 리스크

- **[리스크] 1000명 동시접속 목표와 2일·1인 개발 제약의 긴장 관계**: "최대 1000명 동시접속 지원"은 비즈니스 목표로 유지하되, 2일 MVP 범위에서는 이를 실제로 검증(부하 테스트, 오토스케일링, 캐시 레이어, 커넥션 풀 튜닝 등)하지 않는다. 대신 무상태 API 서버, DB 커넥션 풀 사용 등 **확장 가능한 구조를 기본으로 채택**하는 선에서 대응하며, 로드밸런서·오토스케일링·캐시 레이어 등 추가 인프라는 이번 범위에 포함하지 않는다. 실제 1000명 동시접속 검증은 MVP 이후 별도 단계로 넘긴다.
- **[리스크] OCR/AI 비전 정확도 미검증**: 도메인 정의서 8절에서도 지적되었듯 인식 방식이 미정이며, 예산 제약(사실상 없음)상 유료 고정확도 API 사용이 어려울 수 있다. 인식 실패/저정확도 시 사용자 보정(FR-3.4)으로 보완하는 것을 전제로 하되, 2일 내 검증 가능한 무료/저비용 방식을 사용한다고 가정한다.
- **[리스크] 4단계 전체 기능을 2일 내 완성하지 못할 가능성**: 1인 개발 특성상 일정 지연 시 FR-3(OCR/AI 비전)의 자동 인식 정확도를 낮추고 수동 입력 보정 비중을 높이는 방식으로 축소한다.
- **[가정] 인증 방식**: 별도 지시가 없어 이메일/비밀번호 기반의 가장 단순한 인증 방식을 채택한다고 가정한다. 소셜 로그인은 범위 밖이다.
- **[가정] 배포 환경**: 예산이 사실상 없다는 제약에 따라, 무료 티어 수준의 클라우드 환경 또는 로컬 시연 환경을 사용한다고 가정한다. 구체적 배포처는 9절 확인 필요 항목이다.

## 9. 확인이 필요한 사항 (PRD 레벨)

도메인 정의서 8절의 항목(설문 문항 확정, 판정 임계값, 이미지 보관 정책 등)과 중복되지 않는, PRD 수준에서 새로 발생한 질문만 정리한다.

- **인증 방식 구체화**: 이메일/비밀번호 방식으로 가정했으나, 토큰 방식(JWT 등)과 세션 만료 정책을 구체적으로 어떻게 할지 확정 필요
- **OCR/AI 비전 구현 수단**: 2일 내 예산 제약 하에 사용할 구체적인 OCR/비전 라이브러리 또는 API(무료 티어 여부 포함) 확정 필요
- **배포 환경**: 실제 배포처(클라우드 무료 티어, 로컬 시연 등)와 도메인/HTTPS 적용 여부 확정 필요
- **1000명 동시접속 목표의 검증 시점**: 부하 테스트·인프라 튜닝을 MVP 이후 어느 단계에서, 어떤 방식으로 진행할지 확정 필요
- **업로드 이미지 제약**: 스크린샷 파일 형식/용량 제한 등 업로드 정책 확정 필요

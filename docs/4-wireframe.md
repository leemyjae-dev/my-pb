## 1. 화면 목록 및 화면 흐름 개요

### 1.1 화면 목록

|---|---|---|---|
| 1 | 회원가입 화면 | FR-0.1 | 시나리오 1 |
| 2 | 로그인 화면 | FR-0.2, FR-0.4 | 시나리오 1, 시나리오 7 |
| 3 | 홈/대시보드 화면 (진단 현황 허브) | FR-0.3, FR-4.1, FR-4.6 | 시나리오 1, 시나리오 6 |
| 4 | 투자자성향(KYC) 설문 화면 | FR-1 | 시나리오 2 |
| 5 | IPIP 신경성 검사 화면 | FR-2 | 시나리오 3 |

| 7 | 자산 항목 확인/보정 화면 | FR-3.3~FR-3.5 | 시나리오 4 (대안 흐름 포함) |
| 8 | 종합 진단 결과 화면 (입력 누락 / 정합 / 괴리 / 괴리+심리부담 상태) | FR-4.1~FR-4.6 | 시나리오 5, 시나리오 6 |

> 화면 3(홈/대시보드)은 PRD·시나리오 문서에 화면으로 명시되어 있지 않다. 다만 FR-4.6("부족한 항목 안내" 후 사용자가 시나리오 2/3/4로 이동 가능해야 함)과 FR-0.3(로그인 후 진단 기능 접근)을 만족시키려면 로그인 이후 3가지 입력 현황을 한눈에 보고 각 기능으로 이동할 수 있는 화면이 필요하다고 판단해 최소 구성으로 추가했다. 상세 판단 근거는 3절 참조.

### 1.2 화면 이동 흐름

```
[비로그인 상태]
   |
   v
+-------------+        +-------------+
| 1.회원가입   | -----> | 2.로그인     |
+-------------+  가입   +-------------+
                  후 이동      |
                          로그인 성공
                               v
                     +-------------------+
                     | 3.홈/대시보드      |<-------------------------------+
                     | (KYC/IPIP/잔고     |                                |
                     |  현황 + 종합진단)  |                                |
                     +-------------------+                                |
                       |        |        |                                |
             KYC 응시   |        |        |  잔고 업로드                    |
                        |        |  IPIP 응시                             |
                        v        v        v                               |
              +----------+ +----------+ +------------------+              |
              | 4.KYC     | | 5.IPIP   | | 6.잔고 업로드     |              |
              |  설문     | | 검사     | +------------------+              |
              +----------+ +----------+           |                       |
                    |            |          업로드/인식 완료               |
              제출 후 대시보드로  제출 후 대시보드로     v                    |
                    복귀         복귀        +------------------+          |
                     \            \          | 7.자산 항목       |         |
                      \            \         |   확인/보정       |         |
                       \            \        +------------------+         |
                        \            \                |                   |
                         \            \        확정 완료 후 대시보드로 복귀  |
                          \            \_______________|___________________+
                           \___________________________|___________________+
                                                         
                     +-------------------+
                     | 종합 진단 확인 요청 (대시보드에서)
                     v
                     +-------------------+
                     | 8.종합 진단 결과   |
                     |  - 입력 누락 상태  |---> (부족한 화면 4/5/6으로 이동)
                     |  - 정합/괴리/     |
                     |    심리부담 상태   |
                     +-------------------+
```

- 로그인하지 않은 사용자가 진단 관련 화면(3~8)에 접근을 시도하면 로그인 화면으로 이동한다 (FR-0.3).
- 화면 4/5/6은 응시·업로드 완료 후 홈/대시보드로 복귀하는 것을 기본 흐름으로 한다 (재응시/재업로드 시에도 동일 화면 재사용).
- 화면 8은 대시보드에서 "종합 진단 결과 확인"을 요청했을 때의 도착 화면이며, 입력 3종이 모두 갖춰졌는지에 따라 보여주는 상태가 달라진다 (2.8절 참조).

- 확정 완료 시 화면 3(대시보드)으로 이동

## 3. 확인이 필요한 UI/UX 판단 사항

아래 항목은 PRD·시나리오 문서에 명시적인 근거가 없어, 화면 흐름을 완성하기 위해 최소한의 수준에서 임의로 판단한 레이아웃/구조 사항이다. 실제 구현 전 확인이 필요하다.

- **홈/대시보드 화면의 존재 여부와 구성**: 문서에 별도 화면으로 명시되어 있지 않으나, FR-0.3(로그인 후 진단 기능 접근)과 FR-4.6(부족 항목 안내 후 해당 화면으로 이동 가능해야 함)을 만족하려면 진단 현황을 모아 보여주는 허브 화면이 필요하다고 판단해 최소 구성(3개 상태 카드 + 종합 진단 버튼)으로 추가했다.
- **KYC/IPIP 설문 화면 구성 방식**: 10개 문항을 한 화면에서 스크롤로 모두 노출하는 방식으로 가정했다. 문항별로 한 개씩 넘기는 스텝(마법사) 형태일 수도 있으며, 문서에는 명시되어 있지 않다.
- **잔고 업로드와 자산 항목 보정을 별도의 두 화면으로 분리**: 업로드 진행 상태(인식 처리 중)와 보정 작업(항목별 확인/수정)의 성격이 달라 두 화면으로 나누었다. 업로드 후 같은 화면에서 바로 보정 목록을 이어서 보여주는 단일 화면 구성도 가능하다.
- **종합 진단 결과 화면에서 입력 누락 상태를 별도 화면이 아닌 하나의 상태로 처리**: 작업 지시에 따라 별도 라우트 대신 동일 화면의 한 상태로 구성했으나, 실제로는 "종합 진단 결과 확인" 버튼을 대시보드에서 비활성화하고 결과 화면 진입 자체를 막는 방식도 대안이 될 수 있다.
- **원본 스크린샷 미리보기 노출**: 자산 항목 확인/보정 화면에서 사용자가 인식 결과를 원본과 대조할 수 있도록 미리보기 영역을 추가했다. 문서에는 미리보기 제공 여부가 명시되어 있지 않다.
- **데스크톱 표(테이블) vs 모바일 카드형 리스트**: 자산 항목 목록과 자산군별 비교 결과를, 데스크톱에서는 표로, 모바일에서는 세로 카드 목록으로 표현했다. 이는 일반적인 반응형 레이아웃 관행에 따른 임의 판단이며, 문서에 근거는 없다.

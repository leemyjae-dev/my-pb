## 전체 여정 개요

사용자는 회원가입/로그인으로 서비스를 시작한 뒤, 투자자성향(KYC) 설문과 IPIP 신경성 검사를 각각 응시하고, 본인의 증권 계좌 잔고 스크린샷을 업로드·보정하여 세 가지 입력(KYC, IPIP, 잔고)을 모두 갖춘다. 이 세 가지가 모두 준비되면 종합 진단을 요청할 수 있으며, 서비스는 성향기준 비중과 실보유 자산배분을 비교해 정합/괴리를 판정하고, 필요 시 심리적 부담 안내를 더해 최종 리스크 진단 결과를 제공한다. 각 입력(설문 응답, 잔고 스냅샷)은 재응시/재업로드가 가능하며, 종합 진단은 항상 각 입력의 가장 최근 결과를 기준으로 이루어진다.

아래 시나리오는 이 여정을 온보딩부터 최종 결과 확인까지 순서대로 다루며, 각 단계에서 발생 가능한 예외 흐름을 함께 정리한다.

## 시나리오 1. 회원가입 및 로그인 (FR-0)

### 목표
사용자가 계정을 만들고 로그인하여, 진단 관련 기능(FR-1~FR-4)을 이용할 수 있는 상태가 된다.

### 사전조건
- 사용자가 아직 계정이 없거나(회원가입 전), 계정은 있으나 로그인하지 않은 상태다.

### 기본 흐름
1. 사용자가 서비스에 접속한다. → 시스템은 로그인하지 않은 사용자에게 진단 관련 기능(FR-1~FR-4)에 대한 접근을 허용하지 않는다.
2. 사용자가 이메일과 비밀번호를 입력해 회원가입을 요청한다. → 시스템은 계정을 생성한다.
3. 사용자가 이메일과 비밀번호로 로그인을 요청한다. → 시스템은 인증에 성공하면 access_token과 refresh_token을 발급한다.
4. 사용자는 발급된 인증 상태로 진단 관련 기능에 접근할 수 있게 된다.

### 사후조건/기대 결과
- 사용자 계정이 생성되고, 로그인 상태에서 진단 관련 기능(설문 응시, 검사 응시, 잔고 업로드, 종합 진단 확인)에 접근 가능하다.

### 예외/대안 흐름
- 사용자가 로그아웃을 요청하면, 시스템은 인증 상태를 해제하고 이후 진단 관련 기능 접근을 다시 차단한다.
- access_token 만료 시의 재인증 흐름은 시나리오 7(예외 시나리오: access_token 만료 시 재인증)에서 별도로 다룬다.

## 시나리오 2. 투자자성향(KYC) 설문 응시 (FR-1)

### 목표
사용자가 표준 KYC 설문에 응답하여 본인의 공식 투자자성향 등급(5단계 중 하나)을 확인한다.

### 사전조건
- 사용자가 로그인한 상태다.

### 기본 흐름
1. 사용자가 투자자성향 설문 응시를 시작한다.
2. 사용자가 10개 문항 각각에 응답(1~5점)한다.
3. 사용자가 응답을 제출한다. → 시스템은 응답을 100점 환산 총점으로 계산하고, 도메인 정의서에 정의된 구간 기준에 따라 5단계 등급(안정형/안정추구형/위험중립형/적극투자형/공격투자형) 중 하나를 산출한다.
4. 시스템은 문항별 응답, 총점, 등급, 응시 일시를 투자자성향 진단결과로 저장한다.
5. 사용자는 산출된 등급 결과를 확인한다.

### 사후조건/기대 결과
- 사용자에게 투자자성향 진단결과(등급 포함)가 저장되어, 이후 종합 진단(시나리오 5)의 입력으로 사용될 수 있는 상태가 된다.

### 예외/대안 흐름
- 사용자는 언제든 설문을 다시 응시할 수 있으며, 재응시 시 기존 결과와 별도로 새로운 결과가 생성된다. 종합 진단에는 가장 최근 결과가 사용된다.

---

## 시나리오 3. IPIP 신경성 검사 응시 (FR-2)

### 목표
사용자가 IPIP 신경성 검사에 응답하여 본인의 심리민감도(손실민감도) 등급을 확인한다.

### 사전조건
- 사용자가 로그인한 상태다.

### 기본 흐름
1. 사용자가 IPIP 신경성 검사 응시를 시작한다.
2. 사용자가 10개 문항 각각에 응답(1~5점)한다.
3. 사용자가 응답을 제출한다. → 시스템은 역채점 문항의 응답값을 반전(6-응답값) 처리한 뒤 합산해 신경성 총점을 계산하고, 이를 기준값과 비교하여 심리민감도 등급(높음/보통)을 산출한다.
4. 시스템은 문항별 응답, 총점, 등급, 응시 일시를 IPIP 신경성 검사결과로 저장한다.
5. 사용자는 산출된 심리민감도 등급 결과를 확인한다.

### 사후조건/기대 결과
- 사용자에게 IPIP 신경성 검사결과(심리민감도 등급 포함)가 저장되어, 이후 종합 진단(시나리오 5)의 입력으로 사용될 수 있는 상태가 된다.

### 예외/대안 흐름
- 사용자는 언제든 검사를 다시 응시할 수 있으며, 재응시 시 기존 결과와 별도로 새로운 결과가 생성된다. 종합 진단에는 가장 최근 결과가 사용된다.

---

## 시나리오 4. 잔고 스크린샷 업로드 및 보정 (FR-3)

### 목표
사용자가 본인의 증권 계좌 잔고 스크린샷을 업로드하여, 실제 보유 자산의 자산군별 비중을 확정한다.

### 사전조건
- 사용자가 로그인한 상태다.
- 사용자가 본인의 증권 계좌 잔고 화면을 캡처한 스크린샷 이미지를 보유하고 있다.

### 기본 흐름
1. 사용자가 잔고 스크린샷 이미지를 업로드한다.
2. 시스템은 이미지에서 종목명·수량·평가금액을 인식하고, 인식된 종목별로 자산군(주식/채권/펀드/현금성자산 등)을 자동 분류한다.
3. 시스템은 자동 분류 결과를 사용자에게 보여준다.
4. 사용자가 자동 분류 결과를 확인하고 보정 완료를 요청한다. → 시스템은 자산군별 비중을 확정하여 보유잔고 스냅샷으로 저장한다.
5. 사용자는 확정된 자산군별 비중을 확인한다.

### 사후조건/기대 결과
- 사용자에게 자산군별 비중이 확정된 보유잔고 스냅샷이 저장되어, 이후 종합 진단(시나리오 5)의 입력으로 사용될 수 있는 상태가 된다.

### 예외/대안 흐름 — 자동 분류가 애매한 항목의 보정
1. 시스템이 종목별 자산군을 자동 분류하는 과정에서, 일부 항목은 분류가 애매하다고 판단하여 "사용자 보정 필요" 상태로 표시한다.
2. 사용자는 보정이 필요한 항목을 확인하고, 해당 항목의 자산군을 직접 선택하거나 수정한다.
3. 사용자가 보정을 완료하면, 해당 항목은 "사용자 보정 완료" 상태가 된다.
4. 모든 항목이 자동 분류 확정 또는 사용자 보정 완료 상태가 된 뒤에만, 시스템은 자산군별 비중을 계산해 확정 반영한다.
5. 사용자가 보정이 필요한 항목을 그대로 두고 확정을 시도하면, 시스템은 확정을 진행하지 않고 보정이 필요한 항목이 남아 있음을 안내한다.

### 그 외 대안 흐름
- 사용자는 언제든 잔고 스크린샷을 다시 업로드할 수 있으며, 재업로드 시 기존 스냅샷과 별도로 새로운 스냅샷이 생성된다. 종합 진단에는 가장 최근 스냅샷이 사용된다.

## 시나리오 5. 종합 진단 결과 확인 (FR-4)

### 목표
사용자가 투자자성향, 심리민감도, 실보유 자산배분 세 가지를 결합한 종합 진단 결과를 확인하여, 본인의 실제 투자가 성향·심리 대비 적절한지 판단한다.

### 사전조건
- 사용자가 로그인한 상태다.
- 사용자에게 투자자성향 진단결과, IPIP 신경성 검사결과, 보유잔고 스냅샷이 각각 최소 1건씩 존재한다.

### 기본 흐름
1. 사용자가 종합 진단 확인을 요청한다.
2. 시스템은 가장 최근의 투자자성향 진단결과, IPIP 신경성 검사결과, 보유잔고 스냅샷을 각 1건씩 조합한다.
3. 시스템은 투자자성향 등급의 성향기준 비중과 실보유 자산배분을 자산군별로 비교하여 정합/괴리를 판정한다.
4. 시스템은 판정 결과에 따른 피드백 메시지를 생성한다.
5. 시스템은 결과를 리스크 진단 결과로 저장하고 사용자에게 표시한다.
6. 사용자는 종합 진단 결과(정합/괴리 판정, 피드백 메시지)를 확인한다.

### 사후조건/기대 결과
- 사용자에게 리스크 진단 결과가 저장·표시된다.

### 대안 흐름 A — 정합인 경우
- 3단계 판정에서 모든 자산군에 대해 성향기준 비중과 실보유 자산배분이 정합인 경우, 시스템은 긍정적 피드백 메시지를 생성해 결과에 포함한다.

### 대안 흐름 B — 괴리인 경우
- 3단계 판정에서 특정 자산군에 대해 성향기준 비중과 실보유 자산배분 간 괴리(초과 또는 과소)가 발견된 경우, 시스템은 해당 괴리에 대한 조정 방향 피드백 메시지를 생성해 결과에 포함한다.

### 대안 흐름 C — 괴리 + 심리민감도 '높음'이 결합된 경우
- 대안 흐름 B의 상황에서, 사용자의 심리민감도 등급이 '높음'인 경우, 시스템은 조정 방향 피드백에 더해 해당 초과 투자가 심리적으로 더 큰 부담이 될 수 있다는 심리적 부담 안내를 함께 결과에 포함한다.

## 시나리오 6. 예외 시나리오 — 입력이 부족한 상태에서 종합 진단 시도 (FR-4.6)

### 목표
사용자가 KYC/IPIP/잔고 세 가지 입력 중 일부가 없는 상태에서 종합 진단을 요청했을 때, 무엇이 부족한지 안내받는다.

### 사전조건
- 사용자가 로그인한 상태다.
- 투자자성향 진단결과, IPIP 신경성 검사결과, 보유잔고 스냅샷 중 하나 이상이 존재하지 않는다.

### 기본 흐름
1. 사용자가 종합 진단 확인을 요청한다.
2. 시스템은 투자자성향 진단결과, IPIP 신경성 검사결과, 보유잔고 스냅샷이 모두 존재하는지 확인한다.
3. 시스템은 셋 중 하나 이상이 없음을 확인한다. → 종합 진단을 진행하지 않고, 어떤 항목이 부족한지 사용자에게 안내한다.

### 사후조건/기대 결과
- 리스크 진단 결과는 생성되지 않는다.
- 사용자는 부족한 항목(투자자성향 설문/IPIP 신경성 검사/잔고 스크린샷 업로드 중 무엇을 완료해야 하는지)을 인지하고, 해당 시나리오(시나리오 2, 3, 4 중 필요한 것)로 이동해 입력을 완료할 수 있다.

## 시나리오 7. 예외 시나리오 — access_token 만료 시 재인증 (FR-0.4)

### 목표
사용자가 로그인 상태에서 서비스를 이용하던 중 access_token이 만료되더라도, 로그인 상태가 끊기지 않고 유지된다.

> 참고: access_token/refresh_token의 구체적인 유효기간, refresh_token 저장 방식, 재발급 실패 시 처리 방식은 PRD 9절에서 아직 확인이 필요한 사항으로 남아 있다. 이 시나리오는 개념 수준의 흐름만 다루며, 구체적인 값은 명시하지 않는다.

### 사전조건
- 사용자가 이전에 로그인하여 access_token과 refresh_token을 발급받은 상태다.

### 기본 흐름
1. 사용자가 로그인 상태에서 진단 관련 기능(설문 응시, 검사 응시, 잔고 업로드, 종합 진단 확인 등)을 이용한다.
2. 사용자가 이용하는 도중 access_token이 만료된다.
3. 시스템(클라이언트)은 access_token 만료를 인지하고, 보유하고 있는 refresh_token을 이용해 새로운 access_token 재발급을 요청한다.
4. 서버는 refresh_token이 유효함을 확인하고 새로운 access_token을 발급한다.
5. 사용자는 별도의 재로그인 없이 이용 중이던 기능을 계속 사용할 수 있다.

### 사후조건/기대 결과
- 사용자의 로그인 상태가 끊기지 않고 유지된다.

### 예외/대안 흐름
- refresh_token마저 만료되었거나 유효하지 않은 경우, 시스템은 재발급을 거부하고 사용자를 로그인이 필요한 상태로 전환한다. 사용자는 다시 로그인해야 한다. (재발급 실패 시 구체적인 처리 방식은 PRD 9절 확인 필요 사항이다.)
